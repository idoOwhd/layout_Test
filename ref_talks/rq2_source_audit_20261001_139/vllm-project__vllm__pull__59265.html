Purpose

Fourth follow-up to #56155, #56156, and #56116; related RFC: #57445.
Depends on #56116. The incremental change is commit
bed877a176:
5 production lines, regression tests, and documentation. The cumulative
GitHub diff includes the prerequisite stack while those PRs remain open.
Review only this follow-up with the
incremental comparison.

OffloadingConnector currently requests LBHNC, which bypasses the packed
hybrid allocator. On Nemotron-3-Nano with three FP8 K/V and three NVFP4 K/V
layers, this selects a 1,088-token padded manager page and fails at startup:

block stride 557056 != page 156672
a manager block cannot be split into 17 kernel blocks of 64 tokens

For quantization configurations advertising has_layerwise_kv_cache(), let the
allocator select the layout. The existing packed-row offload implementation
then handles KV payloads, quantization scales, and state bytes without format
conversion. Non-layerwise configurations keep LBHNC; HiSparse keeps BLHNC.
No transfer kernels or scheduler behavior change.

Test Result

On 4x GB300, exact stacked Python sources plus the nightly wheel's native
extensions (0.29.1rc1.dev513+g0961bbae2, Torch 2.13.0+cu130, FlashInfer
0.6.18.post1):

  • Exact-source baseline reproduced the startup failure above.
  • Candidate Nano TP4: FULL and PIECEWISE CUDA graphs captured; both FlashInfer
    FP8 and NVFP4 KV paths resolved.
  • After GPU prefix-cache reset, the CPU tier reloaded 83,226,624 bytes and reused
    1,024 tokens from a 1,081-token prompt. All 128 generated token IDs and finite
    log probabilities matched cold generation exactly. Clearing both cache tiers
    and recomputing also matched exactly. Workers exited gracefully.
  • Byte-exact GPU/CPU round trips cover mixed FP8/NVFP4 rows, attention-only and
    attention/Mamba layouts, multiple destination block IDs, and offload chunks
    containing one or three GPU blocks.
  • Broad regression suite on the final fixture: 541 passed, 1 skipped
    (ROCm-only), including the existing non-layerwise tests.
  • Full repository pre-commit passed, including mypy 3.10 and Markdown lint.

Additional controlled 512-token tests on the same dependency versions reproduced
the default unpatched failure and passed exact CPU reload/recompute checks with
both explicit BLHNC on the base and the patched default. Every offload case
reloaded 83,226,624 bytes and reused 1,024 prompt tokens with FULL/PIECEWISE graphs.
The patched default matched both no-offload controls in the first matrix.
Repeats confirmed exact within-process reloads, but cold generation also varied
between independent unpatched no-offload launches. Both strict cross-process
matrices therefore remain failed; this is not a claim of full cross-launch
bitwise reproducibility. GPU resources were released after every case.

  tests/platforms/test_interface.py \
  tests/v1/kv_connector/unit/offloading_connector/test_worker.py \
  docs/features/quantization/modelopt.md

The model smoke used NVFP4 weights, a metadata-only 3-FP8/3-NVFP4 layer-wise KV
recipe, TP4 multiprocessing, FlashInfer attention, CUTLASS MoE, P64, prefix
caching, a 4,096-token context limit, 512 MiB GPU KV per rank, and a 4 GiB CPU
offload budget. It validates cache transparency, not benchmark accuracy.

Scope and Related Work

This validates the built-in CPU tier on a fixed model/recipe/topology. It does
not certify NIXL P/D, LMCache, secondary tiers, or cross-topology canonical
offloading. Packed offloading still copies the complete backing row, including
unused space.

Duplicate-work checks covered RFC comments and open PR searches on September 29:
#53544 optimizes canonical-map derivation, #56953 compacts per-group CPU slots,
and #57216 fixes hybrid partial-tail scheduling. None changes this layout
negotiation; those changes are not duplicated here. #57824 improves the error
for mixed token-sized offload chunks; it does not change layout negotiation.
