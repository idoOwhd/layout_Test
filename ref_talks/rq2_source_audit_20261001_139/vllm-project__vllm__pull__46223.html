Fix Nixl/Mooncake/Offloading connectors forcing HND layout for MSA-ba…
9cf3a66 
…sed models (MiniMax-M3)

Under P/D disaggregation, NixlConnector unconditionally forced HND KV cache
layout for every non-MLA model. MiniMax-M3 uses MSA (fmha_sm100) which is
written and validated against the model's native NHD layout. HND is not a
relabeling for M3 — it applies a non-identity stride permutation (0,1,3,2,4)
swapping block_size and num_kv_heads axes, causing the MSA kernel's
transpose(1, 2) to produce incorrect memory access and crash at warmup.

Fix: only force HND for attention backends that actually support it
(FLASH_ATTN, FLASHINFER, TRITON_ATTN), matching the same guard already in
prefer_cross_layer_blocks. For other backends (e.g. MINIMAX_M3_SPARSE/MSA),
return None so the default NHD layout is used.

Applied the same fix to MooncakeConnector and OffloadingConnector for
consistency.

Fixes vllm-project#46204
