Summary

  • replace AssignCTALayouts' bespoke cloneLoadWithLayout rewrite with a CGA rematerialization plan rooted at the original consumer operand
  • probe the producer slice before inserting ttg.convert_layout; successful rematerialization feeds the consumer directly, while unsupported paths fall back to the ordinary conversion
  • clone ordinary and descriptor loads with their coalesced intra-CTA layout preserved
  • avoid duplicating volatile loads or producer slices with non-exclusive uses

Motivation

The direct load matcher in AssignCTALayouts only handled conversion chains rooted immediately at a load. It could not propagate an assigned CTA layout through elementwise or other rematerializable producers.

The new flow separates analysis from mutation: it first verifies that the full producer slice is rematerializable in the requested CGA layout, then commits the rewrite. This avoids creating a temporary root conversion on the successful path and keeps failure transactional.

This is a stacked draft on #10325.

Validation

  • Added coverage that the rematerialized value is wired directly into tt.dot, without an identity root conversion
  • Full test suite has not been rerun after the latest refactor
