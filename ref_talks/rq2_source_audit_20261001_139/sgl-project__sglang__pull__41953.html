Why?

  • Unified PD exposes whole KV pages and recurrent-state slots. Supporting more peer layouts needs the address of each tensor inside those blocks.

What?

  • Describe MLA rows and recurrent tensors with layer IDs, byte offsets, payload sizes, block strides, and TP shard axes/groups.
  • Keep the raw allocation registered once and preserve the existing whole-block transfer path. This foundation enables no new topology.
  • Stack: 1/3; followed by unequal-TP PD ([PD] Support unequal TP with unified hybrid MLA memory #41956) and matching-DCP PD (Support unified PD between matching DCP peers #41958).

Verification?

  • Expected addressing example (3 layers, 4 rows/page, 16 bytes/row):
Before: page 7 -> one 192-byte transfer block
After:  page 7 / layer 1 / row 2
        -> base + 7*192 + 1*64 + 2*16
        -> 16-byte payload at base + 1440
  • Observed: layout addresses match actual tensor views on fragmented physical pages and state slots, including mixed state dtypes.

Test?

  • Passed: python -m pytest -q test/registered/unit/mem_cache/test_unified_transfer_layout.py plus the existing MLA-view, Mamba-view, and unified-PD move-gate suites: 31 tests, 32 subtests.
  • Passed on H200: existing TestUnifiedMemoryDisaggregationChunkedPrefill::test_logprob_parity, using Mooncake TCP and again using RDMA: 1 test, 1 subtest per run. RDMA connections are confirmed in the test log.
  • Passed on H200 over RDMA: the remaining standard MLA and MHA regressions in test_disaggregation_unified_memory.py: 2 tests, 2 subtests. All three tests in the existing file have passed.
  • Passed: Ruff formatting/checks, isort, compile checks, and git diff --check.
  • Passed in upstream CI: lint and all 12 base-a-test-cpu shards.
  • Pending: targeted H200 GPU CI at c70d9503f9. The unrelated Intel CI runner failed before tests with No space left on device. No performance claim.
